special

Gamma, beta, error and normal functions, incomplete gamma and beta and their inverses, Bessel, zeta and elliptic integrals, measured in ULPs against mpmath.

You are reading the documentation of an outdated version, whose text may no longer be accurate. Go to the latest version.

Special mathematical functions in pure Go (no cgo, no assembly): the gamma family, error functions, incomplete gamma and beta functions and their inverses, Bessel functions, zeta functions, combinatorics, logistic helpers and complete elliptic integrals — with an element-wise layer over go-ndarray.

🌐 Website · 📚 Documentation

It is the numerical foundation of the go-numerics statistics library: every distribution’s cdf and quantile function is computed with these functions, so their accuracy is the product. Each function is measured in ULPs against mpmath at high precision, over its whole domain — tails, zeros, poles, huge and tiny arguments, subnormals, NaN and ±Inf — and SciPy is measured on exactly the same points.

go get github.com/go-numerics/special@v0.5.8
package main

import (
	"fmt"

	"github.com/go-numerics/special"
)

func main() {
	fmt.Println(special.Gamma(4.5))              // 11.631728396567448
	fmt.Println(special.Erfc(10))                // 2.088487583762545e-45
	fmt.Println(special.Ndtr(-30))               // 4.906713927148187e-198
	fmt.Println(special.Ndtri(1e-300))           // -37.0470962993612
	fmt.Println(special.GammaP(2.5, 1.5))        // regularised lower incomplete gamma
	fmt.Println(special.BetaIncInv(2, 3, 0.975)) // a beta quantile
	fmt.Println(special.Jv(2.5, 10))             // Bessel function of real order
}

Arrays (github.com/go-numerics/special/nd): any real dtype in, Float32 kept as Float32, everything else Float64; NumPy broadcasting; large arrays are split across cores.

x, _ := ndarray.Linspace(-5, 5, 1_000_001)
p, _ := nd.Ndtr(x)

A few of them, drawn with go-plot:

package main

import (
	"fmt"

	"github.com/go-numerics/special"
	"github.com/go-plot/plot"
)

func init() { register("bessel", bessel) }

// Bessel functions of the first kind, integer and real order, with Jv.
func bessel() *plot.Figure {
	x := linspace(0, 20, 400)
	fig, axs := plot.Subplots(1, 1, plot.FigSize(6.4, 4))
	ax := axs[0][0]
	for _, v := range []float64{0, 1, 2, 2.5} {
		y := make([]float64, len(x))
		for i, s := range x {
			y[i] = special.Jv(v, s)
		}
		ax.Plot(x, y, plot.Label(fmt.Sprintf(`$J_{%g}(x)$`, v)))
	}
	ax.Axhline(0, plot.Color("gray"), plot.LineWidth(0.8))
	ax.SetTitle("Jv: Bessel functions of the first kind")
	ax.SetXLabel(`$x$`)
	ax.Legend()
	return fig
}
package main

import (
	"github.com/go-numerics/special"
	"github.com/go-plot/plot"
)

func init() { register("gamma", gamma) }

// Gamma on the real line: one curve per interval between its poles at
// 0, -1, -2, -3, so that no line is drawn across a pole.
func gamma() *plot.Figure {
	fig, axs := plot.Subplots(1, 1, plot.FigSize(6.4, 4))
	ax := axs[0][0]
	pieces := [][2]float64{{-4, -3}, {-3, -2}, {-2, -1}, {-1, 0}, {0, 5}}
	for k, p := range pieces {
		x := linspace(p[0]+0.005, p[1]-0.005, 300)
		if k == len(pieces)-1 {
			x = linspace(p[0]+0.005, p[1], 300)
		}
		y := make([]float64, len(x))
		for i, s := range x {
			y[i] = special.Gamma(s)
		}
		if k == len(pieces)-1 {
			ax.Plot(x, y, plot.Color("C0"), plot.Label(`$\Gamma(x)$`))
		} else {
			ax.Plot(x, y, plot.Color("C0"))
		}
	}
	x := linspace(0.05, 5, 200)
	lg := make([]float64, len(x))
	for i, s := range x {
		lg[i] = special.LogGamma(s)
	}
	ax.Plot(x, lg, plot.Color("C1"), plot.LineStyle("--"), plot.Label(`$\log\Gamma(x)$`))
	ax.Axhline(0, plot.Color("gray"), plot.LineWidth(0.8))
	ax.SetYLim(-8, 8)
	ax.SetXLim(-4, 5)
	ax.SetTitle("Gamma and LogGamma")
	ax.SetXLabel(`$x$`)
	ax.Legend(plot.Loc("lower right"))
	return fig
}
package main

import (
	"github.com/go-numerics/special"
	"github.com/go-plot/plot"
)

func init() { register("ndtr", ndtr) }

// The lower tail of the normal distribution and the complementary error
// function, on a log scale, down to the subnormal range of float64.
func ndtr() *plot.Figure {
	x := linspace(-38, 0, 400)
	p := make([]float64, len(x))
	for i, s := range x {
		p[i] = special.Ndtr(s)
	}
	z := linspace(0, 26.5, 400)
	q := make([]float64, len(z))
	for i, s := range z {
		q[i] = special.Erfc(s)
	}
	fig, axs := plot.Subplots(1, 2, plot.FigSize(8, 3.6))
	axs[0][0].Plot(x, p)
	axs[0][0].SetYScale("log")
	axs[0][0].SetYLim(1e-320, 10)
	axs[0][0].SetTitle(`Ndtr($x$)`)
	axs[0][0].SetXLabel(`$x$`)
	axs[0][1].Plot(z, q, plot.Color("C1"))
	axs[0][1].SetYScale("log")
	axs[0][1].SetYLim(1e-320, 10)
	axs[0][1].SetTitle(`Erfc($x$)`)
	axs[0][1].SetXLabel(`$x$`)
	fig.TightLayout()
	return fig
}

Accuracy

Measured on about 250 000 points in 419 regions over 62 functions, this package’s maximum error is at or below SciPy’s in 418 regions (the exception, K1 at small x, is a tie at 1.05 ulp). Typical maxima:

Gamma, LogGamma, Beta (all regions)0.5–1 ulp3–3e15 ulp
Digamma near its negative zeros31 ulp2.5e17 ulp
Erfc to the subnormal range0.5 ulp2e13 ulp
Ndtr lower tail, x in [-38.5, -10)0.5 ulp1.8e12 ulp
Ndtri, ErfInv, ErfcInv0.5–0.6 ulp1.4–4.4 ulp (wrong at subnormals)
GammaP / GammaQ, a in [1e4, 1e15]0.6 ulp8.9e15 ulp

The one area not solved: inverses of the incomplete beta function with a or b far below 1e-3 (both packages can be wrong there).

Full method, sources of every algorithm, negative control and limitations: docs/accuracy.md; every region: docs/accuracy-table.md.

Speed

Accuracy has a price. Measured against SciPy 1.18.1 on one core (refbench, tag v0.8.0, 2026-11-10, 10 000-point calls, host load 6.4–7.9, valid run (151 rows, 2 rounds retried above the gate); ratios are Go time over SciPy time):

  • faster than SciPy: Gamma 0.83 (8.14 vs 9.82 ns/element; nd.Gamma 0.83), LogGamma 0.77, Ndtri 0.57, LogNdtr 0.59, Ndtr 0.84, Erf 0.88, Digamma 0.78, Beta 0.83, the order 0 and 1 Bessel functions (J0 0.76, I0e 0.29, I1 0.96, K1 0.94, K1e 0.39), the elliptic integrals (0.39–0.43), Zeta 0.64, Polygamma 0.05, Comb 0.85, Factorial2 0.02;
  • still slower, the elementwise families, 1.0–1.5x: Erfc 1.01, LogExpit 1.07, Xlogy 1.08, ErfInv 1.12, GammaP and GammaQ 1.15, GammaSign 1.21, LogBeta 1.20, Perm 1.22, Yv 1.22, Expit 1.23, ErfcInv 1.24, Jv 1.28, Logit 1.37, LogSumExp 1.48, GammaPInv and GammaQInv 1.5, Jn 1.52;
  • several times slower, where a double-double continued fraction or series produces the rounded result: Yn 33.4, Iv 8.0, In 5.3, Softmax 5.0, LogSoftmax 4.1, BetaIncInv 3.5, Binom 3.1, Kv 2.3, Xlog1py 2.2, BetaInc 2.1, Kn 1.88, Factorial of non-integers 1.87, Ive 1.71 (open defects, #33).

Since v0.5.6, I1, I1e, K1 and K1e use the same fitted octave interpolants as I0e and K0e (and are more accurate: worst case against mpmath 3.45 to 0.51 ulp for I1); Comb, Factorial2, Factorial and Xlog1py have faster paths that return the same bits as before.

Method and full table: docs/perf.md.

The three without a pairing, and why:

  • Kn — scipy does have kn; this package simply does not measure it against it. The bracketed name is scipy’s, not a measurement.
  • In — scipy has no in, and cannot: it is a Python keyword. Iv at integer order is the equivalent, and In(n, x) is Iv(float64(n), x). Kn/Kv and Jn/Jv stand in the same relation, which is why Jn is bracketed jv: scipy’s jn is a deprecated alias of jv.
  • LogGammaSign — no scipy counterpart in any spelling; scipy splits the two results across gammaln and gammasgn.

The 20 …To slice kernels — GammaTo, ErfTo, XlogyTo and the rest — are the batch form of the function they are named after and compute the same thing, so they share its scipy equivalent rather than earning rows here. One exception is worth knowing: TrigammaTo is exported while Trigamma is not, so that kernel has no scalar form in the public API. It is psi’(x), which scipy spells polygamma(1, x) — the same function Polygamma already provides.

Zeta and HurwitzZeta share one scipy name, zeta(x, q=None), which takes the second argument optionally. LogFactorial is bracketed as a call rather than a name because the function is gammaln with its argument shifted, which is what the harness measures it against.

Complex functions

github.com/go-numerics/special/cmplx (new in v0.4.0) is a drop-in superset of the standard library’s math/cmplx. Changing the import path is enough: the names and signatures are the same, with C11 Annex G special values.

  • New functions: Mul and Div (the Annex G product and quotient), Proj, Log2, Log1p and Expm1.
  • Unchanged from math/cmplx: Abs, Phase, Conj, Polar, Rect, Inf, NaN, IsInf and IsNaN are one call to a correctly specified real function, and are re-exported as they are.
  • Rewritten: every other function. The algorithms are FreeBSD msun’s (as NumPy’s npymath carries them), carried in double-double where float64 loses accuracy.
  • Underlying real functions: sin, cos and tan use this package’s Payne–Hanek reduction, and atan2 is table-driven double-double.
import "github.com/go-numerics/special/cmplx"

cmplx.Tanh(400 + 1i)   // (1+0i); math/cmplx: NaN
cmplx.Log(1 + 1e-10i)  // (5e-21+1e-10i); math/cmplx: real part 0
cmplx.Pow(1i, 2)       // (-1+0i), exactly; math/cmplx: (-1+1.2e-16i)

Each part is measured in ulps against mpmath at 192 and 320 bits. The fixtures cover the tiny, subnormal, huge and near-overflow regions, the branch points, and both sides of every branch cut. Worst part per function:

Each region has a CI budget of 1.5 times its measured maximum, and at least the design’s target. Two budgets sit above the target, and both are open issues:

  • Asinh, Asin, Acos and Acosh: 3 ulp (#26).
  • Pow, region unit: 4500 ulp (#27), inside the design’s (2 + |y log x|) ulp bound.

Every region is listed in docs/accuracy-complex.md, and the design is docs/design-complex.md. Timing against NumPy’s complex ufuncs has not been measured yet.

Double-double arithmetic

github.com/go-numerics/special/dd (public since v0.3.0) is the double-double type the functions above are built on: dd.DD{Hi, Lo} with Add, Sub, Mul, Div, Sqrt, Exp, Log, the exact accumulators Dot, DotDD, Sum, AddProd (every product exact, accumulation in double-double, so an ill-conditioned dot product keeps about 100 bits), and conversions FromInt64, FromBig, Parse (a decimal string to the nearest double-double), (DD).Big, (DD).Float. Relative errors, fuzzed against math/big: Add 3u², Mul 5u², Div 15u²+56u³ (u = 2⁻⁵³); Sqrt is measured (under 8u²). It is the arithmetic behind double-double QR with iterative refinement (the NIST StRD Filip and Wampler problems to 15 digits). ExpMant and ExpReductionMargin expose the exponential’s argument reduction, for callers that must know whether two nearby arguments take the same table entry (go-statistics/stats uses it; it is the single copy of this package).

Portability

Pure Go; CI runs the full accuracy suite on amd64, arm64, 386, arm (32-bit), riscv64, loong64, ppc64le and s390x, compiles the tests for every go tool dist list target, and holds a 100% statement-coverage gate.

One finding along the way: on amd64, Go’s math.Log (assembly) returns about -709.09 for every subnormal argument (it should go down to -744.44); this package never calls it on a value that can be subnormal.
